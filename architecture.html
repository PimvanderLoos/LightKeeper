Architecture

Provisioning pipeline + test-runtime API layers.

A quick map of how Maven, server runtime, agent, and JUnit framework components interact.

Execution flow

1. Real producer lifecycle

lock-build protects outputs before compilation. Maven performs real filtering, generation, Shade and Assembly; prepare-server selects its actual artifact.

2. Cache Resolution

Shared JAR/base caches use ordered kernel leases through rebuild, pruning and copying. Cache identity includes platform/build, Java/OS and agent inputs where applicable.

3. Server Assembly

Worlds, plugins, and overlay files are installed into the target server work directory.

4. Immutable runtime export

Maven publishes module ownership and a complete immutable snapshot tied to its actual JVM identity. Failsafe uses that live export. Direct JUnit invokes a new producer build and accepts only its own successful export.

5. Test Execution

LightkeeperExtension shares prepared inputs within the JUnit launch and creates a private mutable session per class. Processes restart within that session; independent classes receive independent copies. Explicit manifests retain direct directory control.

6. Optional Cleanup

Successful class sessions and owned snapshots are cleaned automatically after use. Failed sessions retain diagnostics; cleanup-server remains optional for prepared work directories.

Module responsibilities

  • lightkeeper-junit-starter: coherent framework, JUnit and assertions on the test classpath
  • lightkeeper-maven-plugin: early build coordination, Maven artifact resolution and runtime export
  • lightkeeper-provisioning: shared providers, downloads, assets, embedded agent, immutable snapshots, and private session copies
  • lightkeeper-runtime-core: runtime manifests and cross-process constants
  • lightkeeper-agent-spigot: in-server command execution and data collection
  • lightkeeper-framework-junit: user-facing handles, extension lifecycle, assertions
  • lightkeeper-protocol: typed commands, responses, and shared values
  • lightkeeper-nms-parent: version-specific internals for low-level behavior
  • lightkeeper-integration-tests: full integration test matrix for supported platforms

For implementation details, read module package docs and integration tests in this repository.
